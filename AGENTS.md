# Stack

- Runtime: Bun API server
- Language: TypeScript, Svelte
- UI: SvelteKit SPA
- Styling: Svelte CSS with Tailwind CSS v4 available
- Data Fetching: TanStack Query
- Linting: Oxlint + oxfmt
- Git Hooks: Lefthook

# Architecture

- Vite serves the UI in dev and proxies same-origin `/api/*` requests to Bun.
- The Bun server owns API routes and serves the built UI for `bun run start`. The game does not use it during play.
- Shared environment parsing lives in `packages/shared/src/env.ts`.
- `packages/game` holds every rule and all content. It is framework-free and deterministic: the random seed lives in the state. The XState machine in `machine.ts` owns the phases, and `reject(world, phase, command)` is the one legality check that the machine's guards, the UI and the bot all use. Never decide legality in a component.
- The host's browser runs the actor and broadcasts the full state after every transition. Peers send commands. There is no state redaction: this is a game for a trusted group.
- `packages/net` is game-agnostic. `apps/signal` is a Cloudflare Worker that only introduces players.
- The game is deployed at https://pandemic-legacy-s2.stf.lol by CI's `deploy` job on every push to master, after the checks pass. It is `apps/signal`'s `production` environment: the same Worker signals on `/signal` and serves `apps/signal/site` as static assets, which `apps/signal/scripts/site.ts` assembles from the UI built for that URL and the scans `scans.generated.ts` names, under `/api/scans/` as in development. Nothing else runs in production, so `/debug/runs` has no runs there. `bun run deploy` deploys from a Mac with env-manager prod's Cloudflare credentials in the environment. The passphrase players type is `SIGNAL_SECRET` in env-manager prod, pushed with `bun run secrets:push`; `bun run secrets:github` sets the repository secrets the deploy uses.
- One partition of the board decides both "unexplored map" and region lines: `nearestLocation(point)` and `regionAt(point)` in `packages/game/src/helpers.ts`. The rules for drawing connections use it (`passage`, `crossesUnexplored`), and the board must draw unknown territory and region lines from the same functions, so what looks blocked is blocked. It is a power diagram: each location's ground is the nearest-location share shifted by its `groundWeight` (content), so its cell edges stay straight and `partition.ts` cuts them exactly. The starting lanes keep clear of ground hidden at the start; `gen-geometry.ts` fails when one cannot.
- Board positions, legal supply-line and sea-lane pairs, and the course each line takes are generated by `apps/ui/scripts/gen-geometry.ts` into `packages/game/src/content/geometry.generated.ts`. Rerun it after changing `content/world.ts`. `routeCourse` is that course: the crossing rules test it, the board draws it, and pawns travel along it, so a line that looks clear is clear.
- Region lines are painted on their own sheet and show only beside a location still hidden, so they fade with the fog.
- The game is in development, so there is no backwards compatibility: `parseSave` only checks a save's shape and refuses one from an older build, and recordings play back as written. Add state without defaults for old saves.
- `apps/playtest` is the playtest lab: AI players, one browser tab each, play the real game through `play <id> <command>` while an audit checks invariants, the Legacy schedule and which mechanics have happened. Its README has the commands. It never decides legality: it lists the engine's options and checks with `reject`.
- Tour games (`apps/playtest/src/stages.ts`) are staged games for the branches a campaign did not take. A stage arranges the table once, on the first action step, and must keep the engine's invariants. `./apps/playtest/lab coverage <run>...` counts what has happened in play from the recordings: it is the evidence that a mechanic works in a real game, and it stands at 227 of 227 (`docs/playtest/tour.md`). A mechanic that only a unit test has reached is not done.
- Who sits where is game state on `world.table` (`packages/game/src/table.ts`), keyed by the id each browser keeps, so every player sees the same table and a reload sits back down. It lives outside the campaign, so a prologue rollback and undo leave it alone. The lobby seats everyone as they arrive (`JOIN`; `ADD_SEAT` for a second hand on one screen) At month 0 everyone readies for the prologue or January, which sets `table.start`. Then, and before every later month (`tableStart`), the lobby is `hud/CharacterSelect.svelte`: every living character card in full, each claimed one (`CLAIM`, or `CREATE_CHARACTER` with a `player`) under its player's colour, name and pawn, where your own name can be edited (`JOIN` renames a seated player). The screen has no backdrop, so the map shows through. Its New character form sets the portrait the character wears (`Character.portrait`, set by `CREATE_CHARACTER`) and lists every starting occupation, crossing out in red the portraits already worn and the occupations `reject` refuses, and a haven under the pointer moves the board's camera to it through Board's `focus`, landing the city where the cards leave the map open. The game starts once everyone is `READY` there, dealing each person the character they claimed or played last (`dealTable`). In a game under way, a browser without a seat picks an open one (`TAKE_SEAT`, through `hud/SeatPicker.svelte`), and Vacate my seat in the menu sends `LEAVE`. The host gets up for anyone who leaves the lobby. `START_GAME` and `SEAT` remain for the bot, the tests and the playtest lab's API players.
- Recordings (`packages/game/src/record.ts`) store state changes, not commands, so a game still replays exactly after a rule changes. The host session and the playtest lab both record through `recordStep`. `/replay` shows a recording on the real `Game` screen through a `ReplaySession`, with `spectator` set so nothing can be sent. `/debug/runs` lists the playtest runs that the Bun server finds under `apps/playtest/runs/` and opens each one in `/replay`.
- Rules reference: `docs/mechanics/`. Keep `docs/mechanics/coverage.md` current when a mechanic is added or changed.

# Environment

- Environment files are managed by `env-manager`. Keep `.env` tracked with harmless defaults and `.env.local` ignored for local values.
- Values live in env-manager's `dev` environment. Edit root `.env.local`, run `env-manager up`, then `bun run env:generate`, and commit the reader exactly as generated. A fresh checkout gets the values with `env-manager down`.
- The server reads settings through `apps/server/src/config.ts`, which fails at startup when production lacks a setting.

# Frontend

- Tailwind CSS v4 is wired through `@tailwindcss/vite`.
- Global styles are imported from `apps/ui/src/routes/layout.css`.
- Theme values live in `apps/ui/src/routes/theme.css` and are selected with `html[data-theme]`.
- Prefer Svelte component CSS for styling. Use Tailwind only for small inline layout utilities when that is simpler than adding a class.
- TanStack Query is configured in `apps/ui/src/routes/+layout.svelte`.
- Imports inside `apps/ui` use the `#lib/*` alias (SvelteKit 3 removed `$lib`), with the file extension for `.ts` files.
- All browser storage goes through `LS` in `apps/ui/src/lib/storage.ts`, which is namespaced by `?DEBUG_ID=`. Never touch `localStorage` directly.
- The board is generated, not drawn: `apps/ui/src/lib/board/chart.ts` paints the chart sheet (paper, coasts, graticule, wear) and the faded sheet that shows over unknown regions. `Fog.svelte` masks between them, so a revealed region inks itself in.
- The board draws only when something changes. `board/frameLoop.ts` stops Threlte's frame loop once nothing has asked for a frame for half a second, the next `invalidate()` starts it again, and a hidden tab draws nothing. The fog's smoke drifts for a few seconds after the board last changed and then comes to rest (`board/Fog.svelte`). So nothing on the board may count on a tick every frame: a `useTask` runs only while the loop does, and one left on `autoInvalidate` keeps the loop running for good. A CSS animation that never ends does the same to the whole page, so a pulse runs a few times and stops. `./apps/playtest/src/perf.ts` measures this: a game nobody is touching must draw 0 frames and name no animation still running.
- Each occupation has a monochrome SVG mark in `apps/ui/src/lib/occupations/icons/<job id>.svg`, drawn in `currentColor` and shown by `OccupationIcon.svelte`, which fails at load when a job in the pack has none. `hud/Portrait.svelte` badges every character's face with it at the bottom left.
- Card faces are generated, never drawn by hand: `apps/ui/src/lib/cards/mapArt.ts` builds the map-and-pin art for any city, used by `PlayerCard.svelte` and `cards/InfectionCard.svelte`. Check changes at `/debug/cards`.
- A player card's text is fitted to the card (`#lib/cards/fit.ts`), never clamped with an ellipsis.
- Every hand is shown in one order: city cards by colour then name, then events, Produce Supplies, companions, epidemics (`sortHand` in `hud/handOrder.ts`). The dock, a seat's piles, and the whole hand a seat lays out while the pointer rests on it all use it.
- City names, populations and permanent structures are printed on the chart in board units (`apps/ui/src/lib/board/print.svelte.ts`), so pieces stand over them. There is no DOM label: each city keeps an empty `.anchor[data-city][data-name]` square lying on the board over its disc and pieces, centred on the disc. The playtest lab finds, reads and clicks cities through it, and it is the city's Feedback tag. Hover text for every piece comes from `board/hints.ts`.
- The stockpile is a piece on the board, a pile of cubes on a fixed patch of open South Atlantic (`board/stockpile.ts` says why that spot is always clear), which the fitted view keeps in frame. Every supply cube that moves flies between it, the cities and the pawns (`supplyMoves`), and lands before it is counted where it lands.
- Every Infection card flipped plays as a scene from `hud/infectionShow.svelte.ts`, driven by the log, so remote players and `/replay` see it too: the card leaves the Infection deck in the top bar (`hud/InfectionDraw.svelte`), the camera finds the city through Board's `focus`, and its cube flies off. An incident is slower: a skull over the empty city becomes the plague cube (`board/Skull.svelte`), then the incident track grows and flashes as its marker lands. The state is never held back: the board shows it late through the show's `lag`, worked out before anything draws (`$effect.pre`), so players act while it plays and the board always ends where the state is. A jump (more than 12 cards, an undo, a replay seek) plays nothing.
- The top bar shows the Player and Infection decks as a card and a count (`hud/Decks.svelte`). Hovering one opens what is known about it: epidemic odds and how many are left, the Infection deck's layers top first, its discard pile that an Epidemic puts back on top, and the cities that would take an incident.
- Actions are chosen three ways, all read from the engine's `actionMenu(world, seat)`, which lists each kind of action a character has with its legal variants or the reason it has none: the Actions panel (`hud/ActionPanel.svelte`, in the side column with room), the ring over a clicked city (`board/Board.svelte`, opened on the side away from the hover slip), and tags over a hand card on hover (`hud/Dock.svelte`). Each one goes through `start()` in `hud/Game.svelte`. A free action that moves an amount (Pick up, Transfer) moves one at a time, since another click or Undo costs nothing (`hud/ways.ts`). If there is only one way, it happens at once. If the ways aim at cities, those cities light for a click on the map, and Escape or a right click cancels. One that moves a pawn (Move a pawn, Airlift) first lights the pawns it can move and their cities, then, once one is picked, where it can go (`aimPawns`). A pickable pawn is clicked through a button over it (`board/Pawn.svelte`), since the city's hover boxes stand in front of it. Anything else opens the chooser. The icons are cut from Codex's sheet `apps/ui/art/action-icons.png` by `apps/ui/scripts/action-icons.ts`.
- Lines that describe game objects show them as glyphs: `hud/RichText.svelte` draws a `Rich` line from `hud/rich.ts` with `board/Glyph.svelte`. `actionDetail` names each card as a glyph in its colour (`cardRef`), and plain text from the engine or the rules gets a glyph before every card, cube and Hollow Man it names (`withGlyphs`).
- The Actions panel shows every kind of action whole, icon, name and full text, in the engine's order, with no scroll and no ellipsis. A list too tall for its column grows a second column (a late-campaign character has up to 23 kinds). Its footer holds whatever moves the turn on: the action pips, End actions and Undo, Draw, Flip infection, and Lockdown for a Lockdown card in the infection discard. The panel is a firm cover for the fitted view (`Covered.firm` in `board/types.ts`): the board never slides under it, and `fitBoard` moves the camera sideways when one side is wider.
- There is no tray at the bottom. The hand floats over the map (`.dock-layer` in `hud/Game.svelte`), between the panels of the side columns that stand beside it however wide they grow (the objectives are centred between those beside them at the top), so the Actions panel's columns mid-side never squeeze it, and the step's slip (a prompt, the draw and infect steps, a lit-city target) stands beside the hand, never above it, so the band the fitted view leaves free stays the hand's height all turn.
- Seats sit in the corners in turn order, clockwise, with this browser's player at the bottom right (`hud/seats.ts`). A browser that plays several characters, such as one playing on its own screen, seats whichever of them is active there. Live play and replays share that layout through `Game.svelte`, where a pointer or focus resting on a seat lights its pawn on the board.
- Development builds load `@stefan.inc/feedback-engine` (`#lib/feedback.ts`): Alt+Cmd+click anything, or choose Give feedback in the Menu, to open the editor, which exports notes with `file:line` and the game's phase and turn. Its ProcrastiMate entry appears when `.env.local` has `PROCRASTIMATE_TOKEN`, a personal token from ProcrastiMate's Settings (an AI account's token cannot upload the image), and opens on the project `a/bg-pandemic-2`. The board's WebGL renderer keeps its drawing buffer in development so the capture can read it. Every component root and region carries `{@attach feedback(...)}` with a short summary as its data, and anything that covers the table is a modal dialog. When you build or change a Svelte screen, row, card, or chart, follow Feedback's accessibility skill: `gh api repos/smirea/feedback-engine/contents/skills/feedback-accessibility/SKILL.md -H 'Accept: application/vnd.github.raw'`.
- Each recon route the players know and have not taken is printed on the board as a box reaching from its city into the region it reveals (`board/ReconBox.svelte`). `reconBoxes(world, phase)` in `packages/game` lists them with their legal recon actions and, when there are none, the reason `reject` gives, so the box greys itself out with the engine's words. `board/reconLayout.ts` places each box clear of cities and names at the fitted view's zoom, and the fitted view includes the boxes. Zoomed out past that view, the boxes shrink with the map, so they never cover what they were placed clear of. A click goes through `clickRecon` in `hud/Game.svelte`.
- HTML drawn on the board sits inside the element the camera controls listen on, and Svelte handles `onpointerdown` at the document, too late to stop the controls capturing the pointer. A clickable piece stops `pointerdown` with a native listener, as `ReconBox.svelte` does.
- The Legacy briefing (`hud/Briefing.svelte`) is structured: the engine pushes each card it read and each unlock with its text (`BriefingEntry`, worded in `packages/game/src/briefing.ts`), and `briefingSections` groups the unlocks under one heading per kind, which the UI and the playtest lab both print. An unlock that is a game piece shows as one: a real `PlayerCard` or `InfectionCard`, cubes, an action icon. When the briefing names objectives, the objective tags wait in the dialog, and on Continue `Objectives.svelte` lifts them off the closing dialog onto the board, then deals the incident diamonds in one at a time.
- Content lives where the original keeps it: 8 packages and 69 dossier doors (`pack.seals`, described in `docs/mechanics/box-contents.md`). Recons, searches, first arrivals, frequencies, objectives, turning points and Legacy cards open them through `openSeal`, and a package's report opens its doors. The Box button in the top bar opens `hud/LegacyBox.svelte`: the packages and dossier sheets sealed or opened, with what each opened one held (`dossierView`), the rulebook (`rulebook`) the stickers left (`stickerStock`), and what Package 6 holds now (`campaign.stored`). It never shows sealed content.
- The Legacy deck (`pack.legacyDeck`) is the 84 printed cards by their printed codes. A card's `halt` stands for the STOP or PAUSE printed on the back of the next card, and `readLegacy` stops there. The pile right of Menu opens `hud/LegacyDeck.svelte`: the cards read so far face up, each with where it is now, and the back of the next card with when it is read. Unread faces never show.
- The printed originals are scanned in `docs/assets` (see its README), served by the Bun server at `/api/scans/`, and indexed by `apps/ui/scripts/gen-scans.ts` into `#lib/scans.generated.ts`. Rerun it after the archive changes. `{@attach scan(() => scans)}` from `#lib/scans.svelte.ts` shows them beside any element while the pointer rests on it (`hud/ScanPeek.svelte`, mounted once in the layout). Legacy cards, opened packages and doors, objective tags, event cards and the ending use it. Attach it only to content already revealed.
- The calendar in the top bar folds when the bar runs out of room: future months first, farthest first, then past months, oldest first. The current month always shows.
- A player sees a new briefing unpacked (`hud/Unboxing.svelte`): each Legacy card, package and door it opened plays as one scene from `openings(briefing)`, its pieces rise out and fly to where they live (`PUT_AWAY`, found by `data-dest` marks through `hud/flight.ts`), and the packaging goes in the trash. Watch again, Read everything (the full `Briefing`) and Continue close it. A spectator keeps the passive `Briefing`.
- `packages/game/src/tabletop.ts` is one real group's campaign after July, written as facts (cards, characters, map, doors) and built into an August lobby by replaying our Legacy schedule along their calendar. Their table ran in a physics sandbox, so the facts record what each of their workarounds stood for, never the workaround. It fails loudly when the replay and the facts disagree. The Menu's Load canonical tabletop save opens it. There is no Tabletop Simulator import.
- `/debug/game` runs the real machine and screen on one client. `window.DEBUG` exposes `getState`, `saveState`, `loadState` and `setState`, and `checkpoint(name)`, `restore(name)` and `checkpoints()` keep the newest 12 named saves per `?DEBUG_ID=`. `upgrade(name)` restores a checkpoint from an older build, filling what it lacks with fresh values (`fillSave`), so a long playtest survives a change to the state; players' saves are still refused.
- `/debug` lists the debugging tools. Add a new one to `TOOLS` in `routes/debug/+page.svelte`.
- `/debug/studio` is where a screen is set up exactly, played on from (one player, every seat) and captured for review. It frames the real game (`/debug/studio/stage`, a solo `GameSession` given a save, which never touches this browser's campaign) in an iframe of a chosen laptop size. A `StudioScene` (`#lib/studio/scene.ts`) is plain JSON that draws a screen again: the viewport, the save, and `ui`, everything the game state does not decide. `Game.svelte` exports `ui()` and `applyUi()` for it:
  - Half-chosen actions (lit cities, the ring, the chooser) are closures, so the scene keeps the clicks that led there (`UiStep`). Every click that starts, aims or picks goes through `step()` in `Game.svelte`, which is how they are made again. Route a new such click through `step()`.
  - A panel that keeps state of its own (a tab, a form, a draft) registers it with `keep(name, read, write)` from `hud/viewState.ts`. A new panel with such state does the same, or scenes lose it.
  - The camera comes from `Board`'s `camera()` and `setCamera()`. Scrolled lists and the pointer are the page's (`#lib/studio/dom.ts`): a hover is put back by `placePointer`, which sends the events a real pointer would and gives every `:hover` rule a twin matching `[data-studio-hover]`.
  - Loading and capturing take every passing transition and animation to its end first (`settled` with `hurry`), so a scene and its picture do not depend on when they were taken. What the board animates itself (a camera glide, a pawn's trip, the fog's drift) runs its course, and an animation mid-flight is not part of a scene.
  - A capture redraws the DOM into a canvas (`modern-screenshot`), so it is close to the browser's pixels, not the same. Shots (scene and picture) live in IndexedDB (`#lib/studio/shots.ts`), newest first in the carousel, and download as one JSON file with the pictures inside.
  - Agents drive it through `window.STUDIO` (`StudioApi` in `#lib/studio/stage.ts`): `await STUDIO.ready()`, `load(sceneOf(scenarios.october()))`, `send(command)`, `bot(n)`, `pin({x, y})`, `settle()`, `scene()`, `capture(name)`, `export(ids)`, `history()` and `rewind(at)`. A tab in the background draws rarely, so `settle()` after a command can take a couple of seconds there.

- Local web host: boardgame-pandemic-legacy-season-2.localhost -> 6190; browser API calls use the /api proxy.
- Ports 6190 (UI), 6191 (API) and 6192 (signal) are the owner's own `bun run dev`. Agents never start, stop or open servers on them. An agent runs its own dev server on a block of its own, with exported variables (they override `.env` and `.env.local`): `UI_PORT=6390 PORT=6391 SERVER_URL=http://127.0.0.1:6391 DEV_SIGNAL_PORT=6392 bun run dev`. Take the next free block of 100 (6390, 6490, ...) and stop it when done. A browser keeps `localStorage` per port, so a save made on one port is not on another.

# Product principles

- The game has the mechanics of Pandemic Legacy: Season 2 on a real world map with the same cities. Geography and art are generic and original. The game's own words carry no story or flavor text; the printed original, story included, shows beside a Legacy card, door or package on hover. The legacy deck unlocks the same mechanics at the same points in the campaign.
- Laptop screens only, no mobile. The entire map is visible by default, and all the main UI fits on one screen with no page scroll.
- The UI is sleek, modern, and concise. Take layout cues from the physical game's table (tracks and decks along the edges, board in the middle).
- Motion matters: state changes animate smoothly, and multi-step events (an epidemic, a route being built, a region revealed, a card played) get compound, sequenced animations instead of a snap.
- Quality of life is a core value: track epidemics, count decks, show draw probabilities, and add similar aids wherever players would otherwise count by hand.
- There is no server during play. The host's browser owns the game state (an XState actor in `packages/game`) and peers sync over WebRTC through `packages/net`.
