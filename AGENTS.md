# Stack

- Runtime: Bun API server
- Language: TypeScript, Svelte
- UI: SvelteKit SPA
- Styling: Svelte CSS with Tailwind CSS v4 available
- Data Fetching: TanStack Query
- Linting: Oxlint + oxfmt
- Git Hooks: Lefthook

# Architecture

- Vite serves the UI in dev and proxies same-origin `/api/*` requests to Bun.
- The Bun server owns API routes and serves the built UI for `bun run start`. The game does not use it during play.
- Shared environment parsing lives in `packages/shared/src/env.ts`.
- `packages/game` holds every rule and all content. It is framework-free and deterministic: the random seed lives in the state. The XState machine in `machine.ts` owns the phases, and `reject(world, phase, command)` is the one legality check that the machine's guards, the UI and the bot all use. Never decide legality in a component.
- The host's browser runs the actor and broadcasts the full state after every transition. Peers send commands. There is no state redaction: this is a game for a trusted group.
- `packages/net` is game-agnostic. `apps/signal` is a Cloudflare Worker that only introduces players.
- One partition of the board decides both "unexplored map" and region lines: `nearestLocation(point)` and `regionAt(point)` in `packages/game/src/helpers.ts`. The rules for drawing connections use it (`passage`, `crossesUnexplored`), and the board must draw unknown territory and region lines from the same functions, so what looks blocked is blocked. It is a power diagram: each location's ground is the nearest-location share shifted by its `groundWeight` (content), so its cell edges stay straight and `partition.ts` cuts them exactly. The starting lanes keep clear of ground hidden at the start; `gen-geometry.ts` fails when one cannot.
- Board positions, legal supply-line and sea-lane pairs, and the course each line takes are generated by `apps/ui/scripts/gen-geometry.ts` into `packages/game/src/content/geometry.generated.ts`. Rerun it after changing `content/world.ts`. `routeCourse` is that course: the crossing rules test it, the board draws it, and pawns travel along it, so a line that looks clear is clear.
- Region lines are painted on their own sheet and show only beside a location still hidden, so they fade with the fog.
- A save written by an older build must keep loading: `parseSave` fills any field the save lacks with a new campaign's default. Add the default there when you add state, and a test like `a save written before a field existed still loads and plays`. Recordings are stored data too: `framesOf` runs every frame through `parseSave`.
- `apps/playtest` is the playtest lab: AI players, one browser tab each, play the real game through `play <id> <command>` while an audit checks invariants, the Legacy schedule and which mechanics have happened. Its README has the commands. It never decides legality: it lists the engine's options and checks with `reject`.
- Tour games (`apps/playtest/src/stages.ts`) are staged games for the branches a campaign did not take. A stage arranges the table once, on the first action step, and must keep the engine's invariants. `./apps/playtest/lab coverage <run>...` counts what has happened in play from the recordings: it is the evidence that a mechanic works in a real game, and it stands at 227 of 227 (`docs/playtest/tour.md`). A mechanic that only a unit test has reached is not done.
- Lobby seats are game state (`campaign.seating`, the `SEAT` command, `tableSeating`), so every player sees the same table. Which pawn a browser plays is local (`mySeats`), and the screen asks when it is not set.
- Recordings (`packages/game/src/record.ts`) store state changes, not commands, so a game still replays exactly after a rule changes. The host session and the playtest lab both record through `recordStep`. `/replay` shows a recording on the real `Game` screen through a `ReplaySession`, with `spectator` set so nothing can be sent. `/debug/runs` lists the playtest runs that the Bun server finds under `apps/playtest/runs/` and opens each one in `/replay`.
- Rules reference: `docs/mechanics/`. Keep `docs/mechanics/coverage.md` current when a mechanic is added or changed.

# Environment

- Environment files are managed by `env-manager`. Keep `.env` tracked with harmless defaults and `.env.local` ignored for local values.
- Values live in env-manager's `dev` environment. Edit root `.env.local`, run `env-manager up`, then `bun run env:generate`, and commit the reader exactly as generated. A fresh checkout gets the values with `env-manager down`.
- The server reads settings through `apps/server/src/config.ts`, which fails at startup when production lacks a setting.

# Frontend

- Tailwind CSS v4 is wired through `@tailwindcss/vite`.
- Global styles are imported from `apps/ui/src/routes/layout.css`.
- Theme values live in `apps/ui/src/routes/theme.css` and are selected with `html[data-theme]`.
- Prefer Svelte component CSS for styling. Use Tailwind only for small inline layout utilities when that is simpler than adding a class.
- TanStack Query is configured in `apps/ui/src/routes/+layout.svelte`.
- Imports inside `apps/ui` use the `#lib/*` alias (SvelteKit 3 removed `$lib`), with the file extension for `.ts` files.
- All browser storage goes through `LS` in `apps/ui/src/lib/storage.ts`, which is namespaced by `?DEBUG_ID=`. Never touch `localStorage` directly.
- The board is generated, not drawn: `apps/ui/src/lib/board/chart.ts` paints the chart sheet (paper, coasts, graticule, wear) and the faded sheet that shows over unknown regions. `Fog.svelte` masks between them, so a revealed region inks itself in.
- Card faces are generated, never drawn by hand: `apps/ui/src/lib/cards/mapArt.ts` builds the map-and-pin art for any city, used by `PlayerCard.svelte` and `cards/InfectionCard.svelte`. Check changes at `/debug/cards`.
- A player card's text is fitted to the card (`#lib/cards/fit.ts`), never clamped with an ellipsis.
- Every hand is shown in one order: city cards by colour then name, then events, Produce Supplies, companions, epidemics (`sortHand` in `hud/handOrder.ts`). The dock, a seat's piles, and the whole hand a seat lays out while the pointer rests on it all use it.
- City names, populations and permanent structures are printed on the chart in board units (`apps/ui/src/lib/board/print.svelte.ts`), so pieces stand over them. There is no DOM label: each city keeps an empty `.anchor[data-city][data-name]` square lying on the board over its disc and pieces, centred on the disc. The playtest lab finds, reads and clicks cities through it, and it is the city's Feedback tag. Hover text for every piece comes from `board/hints.ts`.
- The stockpile is a piece on the board, a pile of cubes on a fixed patch of open South Atlantic (`board/stockpile.ts` says why that spot is always clear), which the fitted view keeps in frame. Every supply cube that moves flies between it, the cities and the pawns (`supplyMoves`), and lands before it is counted where it lands.
- Actions are chosen three ways, all read from the engine's `actionMenu(world, seat)`, which lists each kind of action a character has with its legal variants or the reason it has none: the Actions panel (`hud/ActionPanel.svelte`, in the side column with room), the ring over a clicked city (`board/Board.svelte`, opened on the side away from the hover slip), and tags over a hand card on hover (`hud/Dock.svelte`). Each one goes through `start()` in `hud/Game.svelte`. If there is only one way, it happens at once. If the ways aim at cities, those cities light for a click on the map, and Escape or a right click cancels. Anything else opens the chooser. The icons are cut from Codex's sheet `apps/ui/art/action-icons.png` by `apps/ui/scripts/action-icons.ts`.
- The Actions panel shows every kind of action whole, icon, name and full text, in the engine's order, with no scroll and no ellipsis. A list too tall for its column grows a second column (a late-campaign character has up to 23 kinds). Its footer holds whatever moves the turn on: the action pips, End actions and Undo, Draw, Flip infection, and Lockdown for a Lockdown card in the infection discard. The panel is a firm cover for the fitted view (`Covered.firm` in `board/types.ts`): the board never slides under it, and `fitBoard` moves the camera sideways when one side is wider.
- There is no tray at the bottom. The hand floats over the map (`.dock-layer` in `hud/Game.svelte`), between the side columns however wide they grow (the objectives are centred over the same room), and the step's slip (a prompt, the draw and infect steps, a lit-city target) stands beside the hand, never above it, so the band the fitted view leaves free stays the hand's height all turn.
- Seats sit in the corners in turn order, clockwise, with this browser's player at the bottom right (`hud/seats.ts`). A browser that plays several characters, such as one playing on its own screen, seats whichever of them is active there. Live play and replays share that layout through `Game.svelte`, where a pointer or focus resting on a seat lights its pawn on the board.
- Development builds load `@stefan.inc/feedback-engine` (`#lib/feedback.ts`): Alt+Cmd+click anything, or choose Give feedback in the Menu, to open the editor, which exports notes with `file:line` and the game's phase and turn. Its ProcrastiMate entry appears when `.env.local` has `PROCRASTIMATE_TOKEN`, a personal token from ProcrastiMate's Settings (an AI account's token cannot upload the image), and opens on the project `a/bg-pandemic-2`. The board's WebGL renderer keeps its drawing buffer in development so the capture can read it. Every component root and region carries `{@attach feedback(...)}` with a short summary as its data, and anything that covers the table is a modal dialog. When you build or change a Svelte screen, row, card, or chart, follow Feedback's accessibility skill: `gh api repos/smirea/feedback-engine/contents/skills/feedback-accessibility/SKILL.md -H 'Accept: application/vnd.github.raw'`.
- Each recon route the players know and have not taken is printed on the board as a box reaching from its city into the region it reveals (`board/ReconBox.svelte`). `reconBoxes(world, phase)` in `packages/game` lists them with their legal recon actions and, when there are none, the reason `reject` gives, so the box greys itself out with the engine's words. `board/reconLayout.ts` places each box clear of cities and names at the fitted view's zoom, and the fitted view includes the boxes. Zoomed out past that view, the boxes shrink with the map, so they never cover what they were placed clear of. A click goes through `clickRecon` in `hud/Game.svelte`.
- HTML drawn on the board sits inside the element the camera controls listen on, and Svelte handles `onpointerdown` at the document, too late to stop the controls capturing the pointer. A clickable piece stops `pointerdown` with a native listener, as `ReconBox.svelte` does.
- `/debug/game` runs the real machine and screen on one client. `window.DEBUG` exposes `getState`, `saveState`, `loadState` and `setState`.

- Local web host: boardgame-pandemic-legacy-season-2.localhost -> 6190; browser API calls use the /api proxy.

# Product principles

- The game has the mechanics of Pandemic Legacy: Season 2 on a real world map with the same cities. Geography and art are generic and original. There is no story or flavor text. The legacy deck unlocks the same mechanics at the same points in the campaign.
- Laptop screens only, no mobile. The entire map is visible by default, and all the main UI fits on one screen with no page scroll.
- The UI is sleek, modern, and concise. Take layout cues from the physical game's table (tracks and decks along the edges, board in the middle).
- Motion matters: state changes animate smoothly, and multi-step events (an epidemic, a route being built, a region revealed, a card played) get compound, sequenced animations instead of a snap.
- Quality of life is a core value: track epidemics, count decks, show draw probabilities, and add similar aids wherever players would otherwise count by hand.
- There is no server during play. The host's browser owns the game state (an XState actor in `packages/game`) and peers sync over WebRTC through `packages/net`.
