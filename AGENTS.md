# Stack

- Runtime: Bun API server
- Language: TypeScript, Svelte
- UI: SvelteKit SPA
- Styling: Svelte CSS with Tailwind CSS v4 available
- Data Fetching: TanStack Query
- Linting: Oxlint + oxfmt
- Git Hooks: Lefthook

# Architecture

- Vite serves the UI in dev and proxies same-origin `/api/*` requests to Bun.
- The Bun server owns API routes and serves the built UI for `bun run start`. The game does not use it during play.
- Shared environment parsing lives in `packages/shared/src/env.ts`.
- `packages/game` holds every rule and all content. It is framework-free and deterministic: the random seed lives in the state. The XState machine in `machine.ts` owns the phases, and `reject(world, phase, command)` is the one legality check that the machine's guards, the UI and the bot all use. Never decide legality in a component.
- The host's browser runs the actor and sends every peer what each transition changed (`apps/ui/src/lib/session/sync.ts`): the whole state to a peer whose link just came up or that asks for it (`resync`), then patches of about a kilobyte (`diff` sends a list of plain values whole when that is shorter than its changes, as when a card leaves the middle of a sorted pile). A peer applies them with `applyPatches`, which keeps every untouched part of its state as the object it was, so its screen redraws only what moved, and freezes the result (`frozen`) as immer freezes the host's. The engine may therefore keep an answer by the identity of a frozen part of a state, as `grid` does by the list of lines: never by a part of a draft or of a campaign still being built. Peers send commands. There is no state redaction: this is a game for a trusted group.
- What players draw on the map, their pings and their cursors are not game state (`session/sketch.svelte.ts`, and presence on the lossy lane). A pen stroke travels as the points added to it, an erase as the strokes it left, and the host passes each on to everyone else. A browser that joins is sent what is on the map with the state. The host keeps the strokes in their own storage key (`drawings`, never in the save or a command), written at most once a second while the browser is idle and as the page goes away, so a reload of the host brings them back; pings and cursors are not kept.
- The signal Worker sends each browser its ICE servers first (`ice`): Cloudflare TURN relays with credentials it mints from `TURN_KEY_ID` and `TURN_KEY_API_TOKEN`, for players whom no direct connection reaches. Without the key, players connect directly or not at all.
- `./apps/playtest/src/netcheck.ts` is the check for all of this: a host and peers in real browsers over real WebRTC, through the lobby, a loaded save, commands from every browser, drawing, and a reload of a peer and of the host. `--relay` lets nothing connect directly, which proves the relays. Run it after changing `packages/net` or `session/`.
- `packages/net` is game-agnostic. `apps/signal` is a Cloudflare Worker that only introduces players.
- The game is deployed at https://pandemic-legacy-s2.stf.lol by CI's `deploy` job on every push to master, after the checks pass. It is `apps/signal`'s `production` environment: the same Worker signals on `/signal` and serves `apps/signal/site` as static assets, which `apps/signal/scripts/site.ts` assembles from the UI built for that URL and the scans `scans.generated.ts` names, under `/api/scans/` as in development. Nothing else runs in production, so `/debug/runs` has no runs there. `bun run deploy` deploys from a Mac with env-manager prod's Cloudflare credentials in the environment. The passphrase players type is `SIGNAL_SECRET` in env-manager prod, pushed with `bun run secrets:push`; `bun run secrets:github` sets the repository secrets the deploy uses.
- One partition of the board decides "unexplored map" and regions: `nearestGround(point)` and `regionAt(point)` in `packages/game/src/helpers.ts`. Its ground belongs to the locations and to the uncharted ground (`uncharted` in `content/world.ts`): sea and land the printed board never charts (the Pacific beyond the stickers, the Indian Ocean, Central Asia, Tibet, Myanmar), which stays under the fog for good, and the Bay of Bengal, which opens with Jakarta. No line may cross ground that stays uncharted, and `gen-geometry.ts` steers lane courses round it. Anything that cannot be reached is fog of war like this, never a look or a check of its own.
- Board positions, legal supply-line and sea-lane pairs, and the course each line takes are generated by `apps/ui/scripts/gen-geometry.ts` into `packages/game/src/content/geometry.generated.ts`. Rerun it after changing `content/world.ts`. `routeCourse` is that course: the crossing rules test it, the board draws it, and pawns travel along it, so a line that looks clear is clear.
- The red lines that limit sea lanes are the lines printed on the board and its stickers (`redLines` in `content/world.ts`), which `gen-geometry.ts` projects into `pack.redLines`. `passage` counts a course's crossings of them, `gen-geometry.ts` gives each lane its best course within the limit of one, and `chart.ts` paints them in red on the known chart. The edge of the fog is the only mark of where an unexplored region begins; no line is drawn along it.
- The game is in development, so there is no backwards compatibility: `parseSave` only checks a save's shape and refuses one from an older build, and recordings play back as written. Add state without defaults for old saves.
- `apps/playtest` is the playtest lab: AI players, one browser tab each, play the real game through `play <id> <command>` while an audit checks invariants, the Legacy schedule and which mechanics have happened. Its README has the commands. It never decides legality: it lists the engine's options and checks with `reject`.
- Tour games (`apps/playtest/src/stages.ts`) are staged games for the branches a campaign did not take. A stage arranges the table once, on the first action step, and must keep the engine's invariants. `./apps/playtest/lab coverage <run>...` counts what has happened in play from the recordings: it is the evidence that a mechanic works in a real game. The catalogue is 383 keys since content follows the printed archive. No run is kept at the moment: the ones recorded before the catalogue grew were deleted, so nothing counts as shown in play until a campaign is recorded again. A mechanic that only a unit test has reached is not done.
- Who sits where is game state on `world.table` (`packages/game/src/table.ts`), keyed by the id each browser keeps, so every player sees the same table and a reload sits back down. It lives outside the campaign, so a prologue rollback and undo leave it alone. The lobby seats everyone as they arrive (`JOIN`; `ADD_SEAT` for a second hand on one screen) At month 0 everyone readies for the prologue or January, which sets `table.start`. Then, and before every later month (`tableStart`), the lobby is `hud/CharacterSelect.svelte`, in the story's look: every living character, then a blank one to make, as cards with no face of their own (`hud/characters/`), all one shape and grown to fill the table. A card is the character's figure from the waist up, ending on a cut line in its seat's colour, with whoever claimed it (`CLAIM`, or `CREATE_CHARACTER` with a `player`) standing on the cut, where your own name can be edited (`JOIN` renames a seated player). Beside it: the name, the exposure track and a small home haven, then the occupation, abilities and scars as translucent panels down an arch that fills the card's height, empty slots shorter than filled ones, all at one fitted size (`fitGroup`). There are no occupation icons. While the pointer rests on a character you have taken, the faces nobody else wears lie over its foot, and a click puts one on it (`WEAR`). Under the cards, each player's vote is named beside Ready: ready, not ready, or still choosing. The blank card is made by the whole table together: its draft is game state (`table.draft`, changed by `DRAFT`, cleared by `CREATE_CHARACTER`), so every screen shows and edits the same one. It starts as a silhouette with the faces still free at its foot; its arch lists the occupations `reject` allows, and choosing one sends the rest away and opens the home haven, until Change. While the haven list is open, the other cards step aside and a haven under the pointer moves the board's camera to it through Board's `focus`. The pen beside a starting haven names it (`RENAME_HAVEN`, which the engine allows in any lobby), so the table names its three starting havens before the first game; every label reads the name through `cityName`. The game starts once everyone is `READY` there, dealing each person the character they claimed or played last (`dealTable`). In a game under way, a browser without a seat picks an open one (`TAKE_SEAT`, through `hud/SeatPicker.svelte`), and Vacate my seat in the menu sends `LEAVE`. The host gets up for anyone who leaves the lobby. `START_GAME` and `SEAT` remain for the bot, the tests and the playtest lab's API players.
- Recordings (`packages/game/src/record.ts`) store state changes, not commands, so a game still replays exactly after a rule changes. The host session and the playtest lab both record through `recordStep`. Only the host keeps one; a peer's Menu asks the host for it (`record-ask`) to save it, or to keep it in its own library (`keepRecord`) and replay it there. The Menu's items that replace the campaign (import, the canonical save, New campaign) stay with the host, so no peer can erase the table's campaign. `/replay` shows a recording on the real `Game` screen through a `ReplaySession`, with `spectator` set so nothing can be sent. Faster than 1×, the characters and the cast on the radio say nothing and a line under way stops (`hushVoices`), since it would still be speaking about a moment the board has left; their words still show. `/debug/runs` lists the playtest runs that the Bun server finds under `apps/playtest/runs/` and opens each one in `/replay`.
- Rules reference: `docs/mechanics/`. Keep `docs/mechanics/coverage.md` current when a mechanic is added or changed.

# Environment

- Environment files are managed by `env-manager`. Keep `.env` tracked with harmless defaults and `.env.local` ignored for local values.
- Values live in env-manager's `dev` environment. Edit root `.env.local`, run `env-manager up`, then `bun run env:generate`, and commit the reader exactly as generated. A fresh checkout gets the values with `env-manager down`.
- The server reads settings through `apps/server/src/config.ts`, which fails at startup when production lacks a setting.

# Frontend

- Tailwind CSS v4 is wired through `@tailwindcss/vite`.
- Global styles are imported from `apps/ui/src/routes/layout.css`.
- Theme values live in `apps/ui/src/routes/theme.css` and are selected with `html[data-theme]`.
- Prefer Svelte component CSS for styling. Use Tailwind only for small inline layout utilities when that is simpler than adding a class.
- TanStack Query is configured in `apps/ui/src/routes/+layout.svelte`.
- Imports inside `apps/ui` use the `#lib/*` alias (SvelteKit 3 removed `$lib`), with the file extension for `.ts` files.
- All browser storage goes through `LS` in `apps/ui/src/lib/storage.ts`, which is namespaced by `?DEBUG_ID=`. Never touch `localStorage` directly.
- Never put HTML `title` attributes on elements, so the browser's default hover tooltip never appears; use `aria-label` for accessibility or a custom UI tooltip when hover text is wanted.
- `hud/Game.svelte` lays the screen out and wires its parts together. What each part does lives beside it: `hud/boardView.svelte.ts` (what the board is drawn from), `hud/choosing.svelte.ts` (from a click to a command), `hud/mapTools.svelte.ts` (pen, eraser, ping), `hud/panels.svelte.ts` (where the panels over the board sit), `hud/turnAdmin.svelte.ts` (the end of a turn), `hud/gameKeys.ts` (the keyboard), `hud/announcements.svelte.ts` with `hud/Announcements.svelte` (toasts, the banner and the board's pulses), `hud/GameMenu.svelte` (the Menu and what it exports and loads) and `hud/storageFlight.ts`. What a show reads off the log since the state before comes from `hud/logWatch.ts` (`LogWatch`, or `entriesSince` where a show keeps more than the log's place). A new behaviour gets a module of its own in the same way, given what it reads as an object of getters.
- Redraw only what changed. A view built from the game state is all new objects, and Svelte treats a different object as a change, so every part of the board's view is its own `$derived` passed through `reconcile` (`#lib/reconcile.ts`), which hands back the same object while the values are the same. Never fold a part that changes with the pointer (cursors, a hover, a lit pawn) into the same derived as one that is costly to redraw. Whatever makes a canvas or a texture (`board/print.svelte.ts`) reads the values it shows through deriveds of their own, never straight off a prop that is an object. In a list, `{@const item = view.items[id]}` gives each row a value of its own.
- `./apps/playtest/src/interact.ts` measures every interaction with real input on a built app: hovers, pan, zoom, drawing, the ring, dialogs, an action being aimed, a deck's cards laid out, moves, whole turns, undo, the lobby of the canonical save, and moments of a bot's own game that it replays in the browser (the opening deal, an Epidemic, an exposure, the last turn with the time lapse and the spending). No interaction may draw a frame longer than 50 ms. Run it after changing what the board or the HUD is drawn from, with `--month 12 --throttle 4` for the worst case, `--profile <dir>` to see where the script time went and `--trace <dir>` for what the browser did around it (decoding, raster, the GPU). It stops when a scenario leaves the crash screen up (`hud/Crash.svelte`, "The screen broke"): the game catches an error thrown while drawing, so no `pageerror` reports it, and a broken screen otherwise measures as a perfect one.
- Three things cost frames without showing up as script, and each was measured:
  - A node added to or removed from straight under a `<canvas>` costs the browser about forty times what it does elsewhere, and Threlte mounts the scene there. So `Board.svelte` wraps the scene in a `<div hidden>` inside the canvas.
  - A `backdrop-filter` is a render pass of its own every time anything behind it changes, which over the board is every frame it draws. Nothing that stands over the board has one: a panel's fill is opaque enough to read without. The one behind the lobby's characters is the exception, a single pass.
  - An animation of anything but `transform` and `opacity` repaints every frame. `Beacon` turns a gradient behind a mask and fades its glow for that reason; do the same in a new one.
- The board is generated, not drawn: `apps/ui/src/lib/board/chart.ts` paints the chart sheet (paper, coasts, graticule, wear) and the faded sheet that shows over unknown regions. `Fog.svelte` masks between them, so a revealed region inks itself in.
- The board draws only when something changes. `board/frameLoop.ts` stops Threlte's frame loop once nothing has asked for a frame for half a second, the next `invalidate()` starts it again, and a hidden tab draws nothing. The fog's smoke drifts for a few seconds after the board last changed and then comes to rest (`board/Fog.svelte`). So nothing on the board may count on a tick every frame: a `useTask` runs only while the loop does, and one left on `autoInvalidate` keeps the loop running for good. A CSS animation that never ends does the same to the whole page, so a pulse runs a few times and stops. `./apps/playtest/src/perf.ts` measures this: a game nobody is touching must draw 0 frames and name no animation still running.
- Every character is a figure: a waist-up cutout on a transparent background in `apps/ui/static/figures/` (`survivor-<n>` for the portraits anyone may wear, one per found occupation that brings its own person, `haven-worker`, and `unknown` for a character not made yet), drawn by Codex through `apps/ui/scripts/gen-figures.ts`, which shows it the story's cast as people the figures must not look like. Every figure looks to the viewer's right, so one standing on the right of a card or the screen is mirrored to look in. Only the cut line ends a figure: its head, hands and glow may spill past the card's other edges. `hud/Portrait.svelte` is a headshot cut from the figure at the head the script found (`#lib/characters/figures.generated.ts`), on the seat's colour; a seat card in a corner carries the seat's supply cubes along its foot (`hud/Corner.svelte`).
- Card faces are generated, never drawn by hand: `apps/ui/src/lib/cards/mapArt.ts` builds the map-and-pin art for any city, used by `PlayerCard.svelte` and `cards/InfectionCard.svelte`. City player cards run the map full bleed with no border, right-align a port anchor beside a single-line fitted title, show live deck copy state in the footer (solid pip in hand/deck, hollow pip in discard, trash icon when out of play via `Game.svelte`'s `card-copies` context), render unscratched searches as minimized translucent bars over the map and scratched non-companion searches as revealed parchment instruction boxes (`searchResultPrint` in `playerPrint.ts`; a companion's box gives way to the companion it found), with every search showing its card to the whole table as the box scratches open (`hud/RevealShow.svelte`), replace the map with full-bleed Codex companion portraits (`apps/ui/static/companions/<companionId>.webp`) and boxless scrim text when a companion is discovered, and show game-end upgrades as a diagonal parchment sticker over the map (floating above the card only when a discovered companion fills the card face). Infection cards share a uniform `11em × 7.2em` shape across city, improved, and Hollow Men cards, keep the city name at the bottom for `TurnDesk` stacking without coordinates or an `"Infection"` kicker, and display Infection upgrades as diagonal parchment stickers over the night map. Event cards carry original monochrome transparent emblems in `apps/ui/static/events/<eventId>.webp` (generated by Codex, referenced via `eventArtUrl`) anchored bottom-right behind boxless text with full-bleed headers and a bottom-left leaf timing tag. Keep card content boxless and adapted to the digital medium (e.g. `X uses left` instead of physical scratch checkboxes and warnings covered elsewhere in the UI). Check changes at `/debug/cards`. A card's colour anywhere else (a seat's pile, a glyph, a deck's tally) is `cardColor` in `hud/PlayerCard.svelte`: the top of its face's gradient from `FACE_COLOR`, by event mode for events, so it never disagrees with the face. A location's colour anywhere is `cityColor(city)` in `board/CityMarker.svelte`.
- Every generated card carries everything its printed card says — full verbatim story, flavor, triggers, instructions, timings, conditions, tracks, scratch-off boxes, and door/package badges — in the printed order and grouping, drawn in our own style. Legacy text comes from `#lib/cards/print.generated.ts` (written by `apps/ui/scripts/gen-scans.ts` from the archive's sidecars), and player and special-card rules and search stories from `#lib/cards/playerPrint.ts`. `LegacyCard.svelte` sends side A to `legacy/Back.svelte`, objective, event, epidemic, scanner, plan and reckoning faces to `legacy/SpecialFace.svelte`, and every other face to `legacy/DocFace.svelte`. An Event's and an Epidemic's face are drawn once, by `cards/EventFace.svelte` and `cards/EpidemicFace.svelte`, for the Player card and the Legacy card alike (`roomy` is the Legacy card's proportions). Once Door R / 55 (`epidemicFromStorage`) is open, Epidemic cards render the torn `"2-It's wearing off"` sticker over Step 2. A scratch-off box shows its revealed text and instructions only once the campaign records it. `/debug/cards` shows every Legacy card's two sides beside their scans.
- A player card's text is fitted to the card (`#lib/cards/fit.ts`), never clamped with an ellipsis.
- Every hand is shown in one order: city cards by colour then name, then events, Produce Supplies, companions, epidemics (`sortHand` in `hud/handOrder.ts`). The dock, a seat's piles, and the whole hand a seat lays out while the pointer rests on it all use it.
- City names, populations and permanent structures are printed on the chart in board units (`apps/ui/src/lib/board/print.svelte.ts`), so pieces stand over them. There is no DOM label: each city keeps an empty `.anchor[data-city][data-name]` square lying on the board over its disc and pieces, centred on the disc. The playtest lab finds, reads and clicks cities through it, and it is the city's Feedback tag. Hover text for every piece comes from `board/hints.ts`.
- The rules text the map stickers print (which first arrival opens what, the haven in ruins, the wall around Utopia and then the Plan, the recon out of Kolkata nobody knows yet) comes from `mapNotes(campaign)` in `packages/game`, each only while it applies, and is printed on the chart beside its location by `board/MapNote.svelte`, placed by `layoutNotes` in `board/labels.ts` clear of discs and names. Recon costs live on the recon boxes. The rule the red lines stand for ("A sea lane cannot cross more than one red region line.") is a note too, to the left of the first red line in sight (`redLines` lists the Cape line south of Johannesburg first, then the rest in the order the campaign reveals them), on ground clear of the fog.
- The stockpile is a piece on the board, a pile of cubes on a fixed patch of open South Atlantic (`board/stockpile.ts` says why that spot is always clear), which the fitted view keeps in frame. Every supply cube that moves flies between it, the cities and the characters (`supplyMoves`), and lands before it is counted where it lands. A cube a character takes or gives is the cube on its seat's card: it flies over the screen between the card and the board (`hud/cubeFlights.svelte.ts`, which Scene's `handover` hands it to), leaving the card as it takes off and joining it only when it lands.
- Every Infection card flipped plays as a scene from `hud/infectionShow.svelte.ts`, driven by the log, so remote players and `/replay` see it too: the card leaves the Infection deck on the turn desk (`hud/TurnDesk.svelte`), the camera finds the city through Board's `focus`, and its cube flies off. An incident is slower: a skull over the empty city becomes the plague cube (`board/Skull.svelte`), then the incident track grows and flashes as its marker lands. The state is never held back: the board shows it late through the show's `lag`, worked out before anything draws (`$effect.pre`), so players act while it plays and the board always ends where the state is. How long a card is held follows what rides on it (`HOLD` in the show): a cube from a city with cubes to spare goes quickly, a city left with one cube or none is held longer, and an incident with the track nearly full longest of all. A jump (more than 12 cards, an undo, a replay seek) plays nothing. Through an Infect step the cities with no cubes that a card still in the deck could strike (`insights().infection.atRisk`) wear a thin red ring on the board (`threats` in `hud/Game.svelte`). Every card turned over is a command of its own (`DRAW`, `INFECT`, an Epidemic's step), so every screen sees it at the same moment and no browser flips a card the others have not seen. A rule that turns over several cards takes one command per card, never a loop inside one command.
- Whatever a Monitor or Cautious Approach turns over, and every search box scratched, is shown to the whole table in front of the board by `hud/RevealShow.svelte`, from the pending step at the front of the queue (`reveal` or `search`), never from a timer. Each card is turned over by a `DECIDE` of its own, the cards reach a hand or the discard pile only when its player puts them away, and a search's result happens only when its player continues, so every screen moves through it together and what it opens is unpacked after it.
- Game End's population step plays as a scene from `hud/populationShow.svelte.ts` once the spending step opens: the camera finds each location whose population moved, one at a time, its disc turns to the new number and a flag says `+1 Supply center` or `−1 Plague`. The board shows each late through the show's `lag`, so the state is never held back; a browser that did not see the game close (a reload, a replay seek) plays nothing, and a Legacy briefing read at game end goes first. The spending sheet (`hud/Upkeep.svelte`, its offers from `hud/upkeepShop.ts` over the engine's `legalPurchases`) has a section per way to spend, production units as orange pips, and the allocations at its foot, each undoable (`REFUND`) until everyone at the table has voted Done (`FINISH_UPKEEP`). While the show plays, or after its own Show board, it steps aside into the right column as a firm cover, so the board stays readable and pannable beside it.
- The top bar shows the Player and Infection decks as a card and a count (`hud/Decks.svelte`), and once unlocked or active, Package 6 (`hud/StorageDeck.svelte`), the Frequency Scanner (`hud/FrequencyScanner.svelte`), the Hollow Men supply counter (`hud/HollowSupply.svelte`), and an active-effects pill (`hud/CampaignStatus.svelte`) listing Lab Breakthroughs, Pearl Lab sample doses & carrier, Turning Points, and Relief supply. Hovering a deck opens what is known about it: epidemic odds and how many are left, the infection rate track and the Infection deck's layers top first, its discard pile that an Epidemic puts back on top, and the cities that would take an incident. The four counters whose slip only explains them (the Frequency Scanner, the Hollow Men supply, Problematic cities and the active-effects pill) are each a `hud/TopTip.svelte`: the counter, its slip, and which one is open kept for a studio scene; a new counter in the bar uses it. The pointer can walk into the deck and Package 6 tooltips (`hud/hoverTip.svelte.ts`), and resting on a section, or reaching it with the arrow keys (Tab pings the map), lays that section's cards out beside the tooltip in `hud/CardSpread.svelte`. A section shows only cards the players may know: a deck's cards as a set where the tooltip counts them, discard piles and set-aside cards, never an undrawn deck's order. Clicking Monitor or the Frequency Scanner opens `hud/ScannerDialog.svelte`, where players inspect or scratch frequencies directly on the dial. Hovering the `Complete the Plan` objective tag previews live card `11-05b` with completed steps checked off. Resting on the Problematic cities count (`hud/AtRisk.svelte`) or the Hollow Men counter points at their cities on the board (`spot` on a city's view, through `onspot`): a red `Beacon` with the city's odds above it in the display face, or a violet one on each city holding Hollow Men. While the next Infect step could turn over cards nobody can name yet, the Problematic cities list, whose cities are grouped by their chance like this too, also has a Could come up section: every city with a chance, grouped by that chance, lit on the map red for the top chance, yellow for the next and grey for the rest (all grey when every city is as likely).
- Actions are chosen three ways, all read from the engine's `actionMenu(world, seat)`, which lists each kind of action a character has with its legal variants or the reason it has none: the Actions panel (`hud/ActionPanel.svelte`, in the side column with room), the ring over a clicked city (`board/Board.svelte`, opened on the side away from the hover slip), and tags over a hand card on hover (`hud/Dock.svelte`, including direct per-box Search tags and Local / System-Wide Produce Supplies tags, plus direct card click for Produce Supplies with engine refusal feedback when unavailable). Each one goes through `start()` in `hud/choosing.svelte.ts`, which holds everything between a click and a command. A free action that moves an amount (Pick up, Transfer) moves one at a time, since another click or Undo costs nothing (`hud/ways.ts`). An action happens only once the player has clicked everything it takes (`remaining` in `choosing.svelte.ts`): a choice with a single answer is still asked, a lit city, pawn or card waiting for its click, and only what the click that started it already picked counts as picked (the city of the ring, the card of a tag). An action that takes nothing, such as Make supplies, happens at once. Every choice after that is made on the game itself, never from a list: if the ways aim at cities, those cities light for a click on the map, and Escape or a right click cancels. One aimed at a player (Share Knowledge, Transfer, Transmit, Call a pawn over, Take a card) lights their pawns and seats (`aimSeats`). One that moves a pawn (Move a pawn, Airlift) first lights the pawns it can move and their cities, then, once one is picked, where it can go (`aimPawns`). A pickable pawn is clicked through a button over it (`board/Pawn.svelte`), since the city's hover boxes stand in front of it. Recon with several routes lights their boxes. An event that takes several places (Team Bravo, Biodome Prototype, Dispersal, Drastic Measures) ticks them on the map with a count on each and is confirmed in the slip. Cards that live off the board (a discard pile, storage, another player's hand, the top of the Infection deck) are laid out as the real cards in front of the table (`hud/CardPick.svelte`) for Broker, Trade, Investigate, Salvage, Rehab, Inoculate, Take a card, It Worked the First Time, Extended Forecast, Data Transfer and the like. A few words in the dock's slip (`dockChoice`) are left only for what the board cannot show: Produce Supplies' mode, how many cubes to carry over, give or take with a player. Deliver moves one cube a click; the Deliveries after it to the same place ride on its action (`delivering:` in the player's `used`). Every flow that discards cards from a player's hand (plus Transmit and `giveCard`: Run, Captain's passage, Carrier drive, Fear of Flying shuttle, Sail/Charter twin copies, Build shelter, Sabotage, Smuggle, Broker/Trade/Investigate, Build supply center with Laborer toggle, Recon, Salvage/Rehab, Lockdown, hand-limit discard, Broken Link `cordon`, `shield`, and `giveCard`) highlights eligible cards directly in the dock hand (`handPick` / pending hand selection) instead of opening a dialog or a list. The icons are cut from Codex's sheet `apps/ui/art/action-icons.png` by `apps/ui/scripts/action-icons.ts`.

- The music is synthesized, never a file: `audio/score.ts` is a `Score` that plays into whatever `ScoreBus` it is given, so the live engine (`audio/music.ts`) and an offline render run the same code.   - A bed of pad and low wind is always there. Nothing falls from the sky until a game is nearly lost: `stormOf` is 0 below a tension of 0.68 (about six incidents and three Epidemics), from there rain comes in and the wind rises, and past 0.84 thunder rolls every quarter of a minute or so. Everything is slow while things are calm and comes closer together as dread rises.

Mark a new beat that turns the story.
  - Levels were set from renders, not by ear: a new voice should sit near its neighbours (a theme about 3 dB over the bed, a cue about 6 dB) and nothing may clip. The weather's levels are the constants at the top of `score.ts`: calm wind sits about 11 dB under the pad, a wave's crest about 2 dB under it, a full storm about 4 dB under the pad of a game in crisis, and thunder about 5 dB over it. `/debug/story` auditions every tone, theme, cue and creature, and has a button for a wave and for thunder.
- Every interaction sound is a function in `audio/foley.ts` that plays into a `Play` (a bus, a time and the Hz of the music's root): `PIECES` (supplies, plague, Hollow Men), `TRAVEL` (one per way a pawn crosses the board, as long as its trip), `MOMENTS` (game start, the Infect step, a turn ending, the rate track, a scar) and `ACTIONS`, which must name every `ActionId`: a sound of its own, or null where its pieces or its vehicle make it. `audio/sfx.ts` plays them on the live engine in the key the score is in (`setSfxKey`), so no pitched sound clashes with the month.

# Product principles

- This is a private digital adaptation of Pandemic Legacy: Season 2 for playing with friends, including the full campaign story, flavor text, character portraits, voiced narrative sequences, procedural SFX, and adaptive ambient music. Holding O swaps a revealed card, door, or package to its scanned original for side-by-side reference. The legacy deck unlocks the exact campaign schedule at every point.
- Laptop screens only, no mobile. The entire map is visible by default, and all the main UI fits on one screen with no page scroll.
- The UI is sleek, modern, and concise. Take layout cues from the physical game's table (tracks and decks along the edges, board in the middle).
- Motion matters: state changes animate smoothly, and multi-step events (an epidemic, a route being built, a region revealed, a card played) get compound, sequenced animations instead of a snap.
- Quality of life is a core value: track epidemics, count decks, show draw probabilities, and add similar aids wherever players would otherwise count by hand.
- There is no server during play. The host's browser owns the game state (an XState actor in `packages/game`) and peers sync over WebRTC through `packages/net`.

[The report format](https://github.com/smirea/feedback-engine/blob/master/spec/report.md) describes the JSON.

- When you build or change a Svelte screen, row, card, or chart, follow the `feedback-accessibility` skill: `.agents/skills/feedback-accessibility/SKILL.md`.
- To see a screen as Feedback reads it, open it in a browser and run `await page.evaluate(() => __feedbackEngine.capture())`. It returns the JSON export without opening the editor. Save it as `feedback.json`, and `bun .agents/skills/feedback-accessibility/scripts/taps.js feedback.json` replays every tap on it.
